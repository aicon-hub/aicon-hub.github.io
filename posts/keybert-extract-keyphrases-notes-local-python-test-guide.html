KeyBERT: find suggested keyphrases in your notes with Python

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

KeyBERT is a Python library that suggests keywords and short phrases for a document. It uses an AI embedding model to compare candidate phrases with the document's overall meaning. That can help you tag notes or start a topic index. It is not a complete summary, and the suggestions need editing. We tried two made-up English paragraphs with a local model: some phrases were useful, but others were repetitive or awkward.

Quick facts

  • What it does: the official documentation describes keyword/keyphrase extraction based on embeddings and cosine similarity. This route does not call a chat assistant.
  • Licence: KeyBERT is MIT-licensed. The separate all-MiniLM-L6-v2 model lists Apache-2.0 on its model card.
  • Setup: KeyBERT 0.9.0 package metadata lists Python 3.8 or newer, but dependencies may need newer Python. Our tested stack used Python 3.10 and sentence-transformers 6.2.0. Use Python 3.10 or newer for this route.
  • Language: our model and stop-word setting were English. Hindi, Malayalam and multilingual alternatives were not tested.
  • Cost: the open-source library is free to download. No payment, card or account was requested in our local test. Optional LLM integrations were not tested.
  • Privacy scope: after the model was cached, our two-sample run worked with networking disabled. Initial setup and model download require internet. This is an observation on one setup, not a network audit.
  • India: India-specific availability was not established. This was a local installation, not an India-location test.

When it helps

If you want suggested labels for a folder of notes, KeyBERT offers a repeatable script instead of a separate conversation for each paragraph. You can keep the text local after downloading the model. It differs from searching notes: search starts with your question, while KeyBERT starts with a document and suggests labels for it. It does not decide what you should study or check whether a document is true.

Our test: two paragraphs, two settings

On 28 October 2026 we ran KeyBERT 0.9.0 with all-MiniLM-L6-v2 on Linux/Python 3.10, using CPU only. The model was already downloaded from an earlier test. We asked for five one- or two-word candidates with English stop words removed, then enabled MMR with diversity 0.7. The documentation describes MMR as a way to make the results less similar to each other.

Sample 1 was about rainwater harvesting. The default list found that topic, but four other results also revolved around rainwater or rain. The diverse list broadened the terms, but included the awkward phrase "storage stored". Sample 2 was a library notice. Its diverse list included "study hours", but neither result list retained both exact closure and reopening dates. These are tags, not a substitute for the notice.

Exact code, including the made-up samples

from keybert import KeyBERT

samples = [
    "Rainwater harvesting collects rain from rooftops and stores it in tanks. "
    "Filters remove leaves and dirt before storage. Stored rainwater can be used "
    "for gardens and cleaning, reducing demand on the municipal water supply.",
    "The college library will close on 3 November for maintenance and reopen "
    "on 10 November. Students must return borrowed books before the closure "
    "to avoid late fines. Evening study hours will be extended after reopening.",
]
model = KeyBERT(model="sentence-transformers/all-MiniLM-L6-v2")
for i, text in enumerate(samples, 1):
    print("SAMPLE", i)
    print("DEFAULT:", model.extract_keywords(
        text, keyphrase_ngram_range=(1, 2), stop_words="english", top_n=5))
    print("DIVERSE:", model.extract_keywords(
        text, keyphrase_ngram_range=(1, 2), stop_words="english", top_n=5,
        use_mmr=True, diversity=0.7))

The numbers are cosine similarity scores, not measured accuracy or probabilities. The diversity setting is a trade-off, not an automatic quality upgrade. With stop words removed, adjacent candidate tokens can form phrases that were not consecutive words in the original. Do not present these suggestions as direct quotations.

We repeated the same code in a network-disabled environment after caching the model and got identical output. We are showing selectable text, not a reconstructed screenshot.

Try the tested route

pip install "keybert==0.9.0" "sentence-transformers==6.2.0"

Use Python 3.10 or newer, save the code above as a Python file and run it. Stay online for the first model download. Start with the made-up samples, then try a short paragraph you own. Read and edit the labels before using them.

Limits

  • Two short English samples only. We did not measure retrieval quality, accuracy, processing speed or suitability for exams.
  • Long documents, PDFs, handwriting, large batches, other languages and other models were not tested. This script takes text, not a document upload.
  • The model card says longer input is truncated beyond its token limit. Do not assume this route covers a whole textbook or long chapter.
  • Do not use keyword extraction to preserve deadlines, amounts or all factual details. Keep the original text alongside suggested tags.
