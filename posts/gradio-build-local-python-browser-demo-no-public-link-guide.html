Gradio: give a Python function a browser interface

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

Gradio turns a Python function into a small browser interface with inputs, a Submit button and outputs. That is useful when you have a script or model and want to try it through a form instead of a terminal. We tested the interface plumbing with a deliberately simple text counter. No AI model was connected, and no public sharing link was created.

Quick facts

  • What it is: an open-source Python package for interfaces around machine-learning models, APIs or ordinary Python functions.
  • Tested: Gradio 6.31.0, Python 3.10.12/Linux, local Chrome browser, three inputs.
  • Cost: the code repository lists Apache 2.0. No account, paid hosting, API key, card or payment was used in this local route. Other hosting routes were not evaluated.
  • Sharing: our server bound only to 127.0.0.1, with share=False and analytics_enabled=False. The official guide says share=True creates a public link. Do not enable that casually for private work.
  • Privacy: synthetic text only. We did not audit network traffic or prove offline operation. A real model/API can introduce separate data flows.
  • India: no India-specific availability was established. This was a local installation, not an India-location access test.

Why use it beside a chatbot?

A chatbot can help write a function. Gradio supplies a reusable form that calls your actual function when someone presses Submit. For a real model demo, the model still needs to be loaded and connected separately. Gradio does not make a counter intelligent, validate a model or turn a prototype into a safe production service.

What we tested

On 28 October 2026 we installed Gradio 6.31.0 and launched a local interface. We typed each sample into its text box and pressed Submit in a real browser. "AI tools need careful tests." returned 5, an empty string returned 0, and "one-two three" returned 2. This measures whitespace-separated pieces, not linguistic words or AI tokenizer tokens. We then restored the five-word example for the screenshot and shut down the server after the test.

Exact tested app

Save this as app.py in a Python 3.10 virtual environment. The tested package metadata requires Python 3.10 or higher. Install the pinned release, then run the app:

pip install "gradio==6.31.0"
python app.py
import gradio as gr

def count_words(text):
    return len(text.split())

demo = gr.Interface(
    fn=count_words,
    inputs=gr.Textbox(label='Text to count'),
    outputs=gr.Number(label='Whitespace-separated tokens'),
    title='Local text counter',
    description='A Gradio interface test. No AI model is connected.',
    analytics_enabled=False,
)
if __name__ == '__main__':
    demo.launch(server_name='127.0.0.1', server_port=7860,
                share=False, inbrowser=False)

Open the local address printed in the terminal, type text and press Submit. The explicit share=False avoids a public sharing tunnel. Keep server_name at 127.0.0.1 for this local exercise. Do not change it to expose the app to a network unless you understand the access implications.

Limits that matter

  • Only a simple text-to-number function was tested. No model inference, files, audio, images, GPU or external API.
  • No authentication, public hosting, tunnel, multi-user load or production deployment was tested. Local binding is not a security audit.
  • The whitespace rule counts a hyphenated expression as one piece. It is not a reliable word count for every language or a substitute for a model's tokenizer.
  • Wrapping a model does not establish its accuracy, rights, costs or privacy. Check those separately.
