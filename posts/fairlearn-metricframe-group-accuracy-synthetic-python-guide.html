Fairlearn: look past a single accuracy score

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

An overall accuracy score does not tell you how errors are distributed. Fairlearn's MetricFrame calculates metrics for the full dataset and for groups you supply. In our eight-row fictional example, overall accuracy was 75%, while group A had 100% and group B had 50%. That is a prompt to investigate the slices, not a fairness verdict about any real model or population.

Quick facts

  • Purpose: disaggregated model assessment. MetricFrame computes metrics overall and by the supplied group feature.
  • Tested: Fairlearn 0.14.0, Python 3.10.12/Linux, eight invented outcomes and predictions. No model was trained.
  • Version scope: we pinned 0.14.0 for the Python 3.10 environment. The current 0.15.0 package requires Python 3.11 or later and was not tested.
  • Cost and licence: the official code repository lists MIT. No account, API key, card, payment or cloud service was used.
  • Privacy scope: invented rows only. The script returned identical output with networking disabled after installation. Not a security audit.
  • India: no India-specific availability established. This was a local package test, not a legal-compliance assessment.

Why use it beside a chatbot?

A chatbot can explain why averages can mislead. MetricFrame calculates the slices from actual arrays and keeps the overall and group metrics together. You choose which groups and metrics matter. The software does not decide whether the data is representative, the groups are appropriate or a system is fair.

Our eight-row test

On 28 October 2026 we supplied two fictional groups, A and B, with four rows each. Both groups had two positive outcomes and two negative outcomes. The predictions matched every A row but predicted zero for every B row. These are intentionally chosen arrays, not demographic data or a real deployment.

Exact tested code

import fairlearn
from fairlearn.metrics import MetricFrame, count, selection_rate
from sklearn.metrics import accuracy_score
# Invented outcomes and predictions. A/B are fictional group labels.
y_true = [1, 1, 0, 0, 1, 1, 0, 0]
y_pred = [1, 1, 0, 0, 0, 0, 0, 0]
groups = ['A'] * 4 + ['B'] * 4
frame = MetricFrame(
    metrics={'accuracy': accuracy_score,
             'selection_rate': selection_rate, 'count': count},
    y_true=y_true, y_pred=y_pred, sensitive_features=groups)
print('Fairlearn', fairlearn.__version__)
print('overall:', frame.overall.to_dict())
print('by group:')
print(frame.by_group.to_string())
print('accuracy max-min:', frame.difference()['accuracy'])

Copied output

Fairlearn 0.14.0
overall: {'accuracy': 0.75, 'selection_rate': 0.25, 'count': 8.0}
by group:
                     accuracy  selection_rate  count
sensitive_feature_0                                 
A                         1.0             0.5    4.0
B                         0.5             0.0    4.0
accuracy max-min: 0.5

Accuracy was 0.75 overall, 1.0 for A and 0.5 for B. The max-minus-min accuracy difference was 0.5, or 50 percentage points. Selection rate here means the fraction predicted as label 1: 0.5 for A and 0.0 for B. It is not an acceptance decision in a real service. Counts are included so the tiny sample sizes stay visible.

We repeated the full script in a process with networking disabled after installation and compared output byte-for-byte. It matched. No model or dataset download was needed for these arrays.

Try the pinned route

Use an isolated Python 3.10 environment, install the tested version, save the code as demo.py and run:

pip install "fairlearn==0.14.0"
python demo.py

Keep sample order aligned across y_true, y_pred and groups. A group label at the wrong index produces a different assessment. Do not infer sensitive attributes from people's names or submit private demographic data just to try this lesson.

What this does not establish

  • Eight made-up rows are too small and artificial for a real-world conclusion. No statistical uncertainty or confidence intervals were evaluated.
  • A metric gap is not, by itself, proof of discrimination. Equal metrics would not prove fairness either.
  • No mitigation algorithm, trained model, dashboard, intersectional assessment or legal standard was tested.
  • Group choice, data quality, context and possible harms need review with the people affected. A number is not a certificate.
