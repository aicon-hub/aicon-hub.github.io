Presidio: find and mask personal details in text with Python

By AiCoN | Published 27 October 2026 | Sources checked 27 October 2026

Presidio is a free Python library. In our script, its analyzer looks through text for personal details such as names, email addresses and phone numbers, and its anonymizer replaces what was found with labels like <PERSON>. You run it on your own computer, so the text does not have to be pasted into an online tool first. It is code, not an app, so it suits people who can run a Python script. On 27 October 2026 we tried it on one made-up message. It caught the name, the email and an Indian PAN-format number, but it needed one extra step for the PAN, and the phone number scored low.

Check by hand: automated detection can miss sensitive details, so masked output is not guaranteed to be safe to share. Read the result yourself before you share anything private.

Quick facts

  • What it is: an open-source toolkit for detecting and masking personal data (PII) in text and images. The project documentation now lives at presidio.dataprivacystack.org, and the GitHub repository sits under data-privacy-stack/presidio (it was microsoft/presidio before).
  • Licence: the GitHub repository lists the MIT License, and the PyPI metadata for presidio-analyzer 2.2.365 lists MIT. The spaCy model we used, en_core_web_sm 3.8.0, lists MIT in its package metadata.
  • Python: PyPI metadata for presidio-analyzer 2.2.365 lists Python 3.10 or newer, below 3.15.
  • India: the supported entities page lists Indian recognizers for PAN, Aadhaar, voter ID, passport, vehicle registration and GSTIN. We tested only the PAN one. We did not find any India-specific availability statement for the software, and did not check further.
  • Cost: the library is free to download. No payment or card was involved in our test.
  • Privacy: after install and the one-time spaCy model download, our run worked with the network switched off. That is one observation on our setup, not an audit.
  • Limit from the project itself: the README says that because Presidio uses automated detection, there is no guarantee it will find all sensitive information, and other protections should be used as well.

Why use it

If you want to share a chat log, a support email or a spreadsheet note with a mentor, a classmate or an online AI tool, you may want the names and numbers removed first. Presidio does that step on your own machine and lets you add or remove what it looks for. The cost is that you set it up and check the result yourself.

What we tested

We used a clean Python 3.10 environment on a small Linux machine (about 1 GB of memory, 2 CPU cores, no GPU) with presidio-analyzer and presidio-anonymizer 2.2.365 and the small English spaCy model. The project's default setup loads the larger en_core_web_lg model, so we chose the small one to fit our machine; results with the larger model may differ. The message is made up, and the phone number and PAN-format string in it are made-up samples.

The code we ran

from presidio_analyzer import AnalyzerEngine
from presidio_analyzer.nlp_engine import NlpEngineProvider
from presidio_analyzer.predefined_recognizers import InPanRecognizer
from presidio_anonymizer import AnonymizerEngine

nlp = NlpEngineProvider(nlp_configuration={
    "nlp_engine_name": "spacy",
    "models": [{"lang_code": "en", "model_name": "en_core_web_sm"}],
}).create_engine()
analyzer = AnalyzerEngine(nlp_engine=nlp, supported_languages=["en"])
analyzer.registry.add_recognizer(InPanRecognizer())   # India PAN, not loaded by default here
anonymizer = AnonymizerEngine()

text = ("Hi, I am Rahul Menon. Email me at rahul.menon@example.com or call +91 98765 43210. "
        "My PAN is ABCPE1234F. Meet me at the Kochi office on Monday.")
results = analyzer.analyze(
    text=text, language="en",
    entities=["PERSON", "EMAIL_ADDRESS", "PHONE_NUMBER", "IN_PAN"])
for r in sorted(results, key=lambda r: r.start):
    print(r.entity_type, repr(text[r.start:r.end]), round(r.score, 2))
print(anonymizer.anonymize(text=text, analyzer_results=results).text)

The output we got

PERSON 'Rahul Menon' 0.85
EMAIL_ADDRESS 'rahul.menon@example.com' 1.0
PHONE_NUMBER '+91 98765 43210' 0.4
IN_PAN 'ABCPE1234F' 0.85
Hi, I am <PERSON>. Email me at <EMAIL_ADDRESS> or call <PHONE_NUMBER>. My PAN is <IN_PAN>. Meet me at the Kochi office on Monday.

What happened: the name and email were found, the PAN-format string was found after we added the India PAN recognizer, and the sentence was masked as shown. The phone number was found with a score of 0.40, which is low. A score is the tool's own number, not a probability that we measured. We limited the search to four entity types, which is why "Kochi" and "Monday" were left alone.

What did not go smoothly

  • In an earlier run with the small model and all default entity types, a PAN-format string was labelled a PERSON, not a PAN, and a few words such as "PAN" and "Monday" were flagged as other entity types. That run produced false positives; we did not compare it with the larger model. Check the output.
  • The India recognizers were not part of the default list in our setup. We added the PAN one by hand.
  • Aadhaar, voter ID, passport, vehicle numbers and GSTIN were not tested, and we did not use any real identity numbers.

Limits of our test

  • One short English message. We did not test long documents, other languages, images, spreadsheets or the larger spaCy model.
  • No screenshot of the run, so the code and output above are the copied text of what we ran.
  • We did not measure how many personal details it misses. Do not rely on it as the only check before sharing a private document.

Try it yourself

  1. Install Python 3.10 or newer, then run: pip install presidio-analyzer presidio-anonymizer
  2. Download the small model: python -m spacy download en_core_web_sm
  3. Save the code above as a file, change the text to your own made-up sample first, and run it. Read the result before using it on anything private.
