tiktoken: count AI tokens, not just words

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

A token is not the same thing as a word. AI text models process chunks of text, and the way text is split can change with the encoding. tiktoken is OpenAI's open-source Python tokenizer: it lets you count those chunks locally. We tested short English, Hindi and Malayalam samples in two encodings. The English sentence used six tokens in both; the Malayalam sample used 50 in one and 12 in the other. These are counts for these exact strings, not a general ranking of languages or models.

Quick facts

  • What it is: the official repository describes a BPE tokenizer for OpenAI models. It splits text into token IDs; it does not generate an answer or judge the text.
  • Licence and setup: MIT-licensed. PyPI lists tiktoken 0.14.0 and Python 3.9 or newer. Our test used Python 3.10.
  • Cost: free open-source library. No API key, payment, card or account was needed in our local test. We did not make a model API call.
  • Scope: counts depend on the exact text and chosen encoding. They are not universal counts for ChatGPT, Claude, Gemini or every OpenAI model.
  • Privacy scope: after the encoding data was cached, our script produced the same results with networking disabled. Initial setup/download needs internet. This is one test, not a network audit.
  • India: India-specific availability was not established. This was a local software test, not an India-location test.

Why count tokens?

If you are building a script that sends text to a model, counting with the correct encoding helps you understand the input size before making a request. It also helps explain why word counts and token counts can differ. OpenAI's help page says spaces, punctuation and partial words contribute, and tokenization varies by model and encoding. Its English rules of thumb are approximations, not a multilingual counting formula.

Our local test

On 28 October 2026 we used tiktoken 0.14.0 on Linux/Python 3.10. We counted three short language samples plus a word with and without a leading space and a digit string. We explicitly selected cl100k_base and o200k_base rather than assuming a model mapping. The character column is Python's len(text), counting Unicode code points, not bytes or necessarily the visible characters a reader perceives. The samples are not a controlled translation benchmark.

Exact code

import tiktoken

samples = [
    "The library opens at nine.",
    "ലൈബ്രറി ഒൻപത് മണിക്ക് തുറക്കും.",
    "पुस्तकालय नौ बजे खुलता है।",
    "apple", " apple", "1234567890",
]
for name in ["cl100k_base", "o200k_base"]:
    encoding = tiktoken.get_encoding(name)
    print(name)
    for text in samples:
        print(repr(text), "characters:", len(text),
              "tokens:", len(encoding.encode(text)))

For these strings: English was 6 tokens in both encodings; Malayalam was 50 versus 12; Hindi was 30 versus 11. The ten-digit string used four tokens, while both "apple" and " apple" used one token each. Equal counts do not mean identical token IDs. We repeated the script with networking disabled after caching the encoding files and got identical output.

What these numbers do not tell you

  • A lower token count does not establish better understanding, translation quality or factual accuracy.
  • These are raw-text counts, not a complete chat request or invoice. Message formatting, tool definitions, output and other API usage can affect totals. Verify actual usage in the API response and current pricing when building a cost estimate.
  • We did not test model responses, paid APIs, chat context limits, other tokenizers or all Indian languages. We did not test OpenAI's browser Tokenizer.

Try it

pip install "tiktoken==0.14.0"

Run the code above with a short made-up string first. To use it with a real model, the repository shows tiktoken.encoding_for_model(model_name). Check that your installed version knows the model, rather than guessing an encoding from a similar name. Keep a local raw-text count separate from full API usage.

The code and results here are selectable text, not a reconstructed terminal screenshot. Do not paste private text into an unrelated website simply to count it.
