MarkItDown: turn Word, Excel and PDF files into Markdown

By AiCoN | Published 27 October 2026 | Sources checked 27 October 2026

MarkItDown is Microsoft's open-source Python tool for turning files into Markdown: readable text with simple markers for headings, lists and tables. It is useful when you want to inspect or prepare document text before putting it into an AI workflow. It does not summarise or answer questions in the local route we tested. We converted three made-up files, a Word notice, an Excel marks sheet and a text PDF. Their text survived, but some structure changed.

Quick facts

  • Purpose: the official README describes conversion for language models and text-analysis pipelines. This is AI-input preparation, not an AI chat app.
  • Licence and setup: the repository and PyPI list MIT. Version 0.1.9 requires Python 3.10 through 3.14.
  • Cost: the open-source library is free to download. No payment or card was requested in our local test. Optional cloud services have separate terms and costs; we did not use or verify them.
  • Privacy scope: our three local-file conversions produced the same output with networking disabled after installation. That is one test, not a network audit. The software also supports URL input and optional cloud/LLM integrations, so this result does not describe all modes.
  • India: India-specific availability was not established. This test was a local Python installation without account sign-in, not an India-location test.

When it helps

For a folder of documents, a small script can extract text into one format that you can review, search or pass to a model. In our samples, a Word list became Markdown bullets and spreadsheet rows became a text table. You can inspect that intermediate text before deciding whether to share it. Conversion alone does not remove private information, make source instructions trustworthy or improve a model's answers.

Our test: three made-up files

On 27 October 2026 we used MarkItDown 0.1.9 on Linux with Python 3.10. We installed the DOCX, XLSX and PDF extras. No API key, external LLM or cloud document service was configured; plugins were explicitly disabled. The files were created for this test, not taken from anyone's documents.

  • Word: one heading, one sentence, two bullet points and a three-row table. The heading and bullets survived. The table contents survived, but the output had a blank header row above the original Item/Amount row.
  • Excel: one sheet with two made-up students and their marks. The sheet name and cell values became a Markdown heading and table. Formulas, charts and multiple sheets were not tested.
  • PDF: a simple text PDF with a bold title and two lines. All words were extracted, but the title became plain text rather than a Markdown heading. This was not a scanned PDF or OCR test.

Exact conversion code

from markitdown import MarkItDown

md = MarkItDown(enable_plugins=False)
for name in ["notice.docx", "marks.xlsx", "guide.pdf"]:
    print("=====", name)
    print(md.convert_local(name).markdown)

Try a local file

  1. Use Python 3.10 through 3.14 in a virtual environment. Install the tested format extras:
pip install "markitdown[docx,xlsx,pdf]==0.1.9"

Then use a file you created or trust:

from markitdown import MarkItDown
md = MarkItDown(enable_plugins=False)
result = md.convert_local("your-notice.docx")
print(result.markdown)

The three-file test script above needs files named notice.docx, marks.xlsx and guide.pdf. Those names refer to our test samples, not files included with the package. Replace them with your own local paths.

Limits and safety

The README says this is not meant for high-fidelity document conversion for human readers. Our examples show why: table headers and PDF heading structure can change. Check extracted text against the original before relying on it, especially numbers, headings and tables.

The README also warns that MarkItDown can access resources available to the process running it. It advises sanitising untrusted inputs and using the narrowest conversion method needed. We used convert_local rather than the general URL/file input method, and left plugins off. These choices do not make unknown files safe. Keep converted content as data, not as instructions to your AI tools.

Not tested: scanned PDFs, OCR plugins, image descriptions, audio, video, password-protected files, complex layouts, formulas, large batches or cloud backends. Optional LLM/cloud features are different workflows and may send content to a service. We did not test them.
