rembg: remove image backgrounds locally with Python

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

rembg is an open-source Python tool that uses image models to separate a foreground subject from its background. It can save the result as a transparent PNG on your computer. That suits people who want a repeatable local editing step rather than uploading each image to a website. We tried the current package on one made-up mug-like drawing. It removed the blue background, but the output had soft, slightly grey edges. This is a synthetic demonstration, not evidence of quality on photographs.

Quick facts

  • What it is: the official README documents a Python library, command line, HTTP server and Docker modes. We tested only the Python library.
  • Version: rembg 2.0.86 with Python 3.11 and CPU inference. Current README requirements say Python 3.11 through 3.13; PyPI metadata lists a broader upper bound. Use the documented 3.11-3.13 range for this route.
  • Licence: rembg is MIT-licensed. Models are separate: we explicitly selected u2net, whose upstream U-2-Net repository carries Apache License 2.0. This does not establish the terms for every model or grant rights to input images.
  • Cost: the library is free to download; no payment, card or account was requested in our local test. Cloud backends and their prices were not tested.
  • Privacy scope: our run succeeded with networking disabled after the model was downloaded. Installation and the initial model download need internet. This is one bounded observation, not a network audit. Optional cloud backends are different.
  • India: India-specific availability was not established. This was a local installation, not an India-location test.

When it helps

The useful part is control over a local editing step: give a script an image, select a model and write a transparent file. A programmer can reuse a model session across several images, as the README demonstrates, although we did not test batch processing. Results still need checking around edges and small details.

Our test: one synthetic drawing

On 28 October 2026 we ran rembg 2.0.86 on Linux/Python 3.11 with no GPU. The input was an 800 x 600 drawing we created: a red mug-like shape against a blue striped background. Its handle was already detached from the body in the input; that gap is not a removal error. We selected u2net by name so the test does not depend on a changing default model.

The output was an 800 x 600 RGBA PNG with an alpha range of 0 to 255. The blue striped background became transparent and the red shape remained. The outline has softness and a visible grey fringe in this comparison. That is enough to demonstrate the workflow, not to rate its performance on portraits, hair, glass or product photographs. The checkerboard is a display backing added for the comparison, not pixels baked into the saved transparent output.

Code we ran

from PIL import Image
from rembg import remove, new_session

session = new_session("u2net")
image = Image.open("in.png")
result = remove(image, session=session)
result.save("output-28.png")
print(result.mode, result.size)
print("alpha range:", result.getchannel("A").getextrema())

Copied output

RGBA (800, 600)
alpha range: (0, 255)

The model was already cached from an earlier setup, where its download was about 176 MB. This run completed with networking disabled. We did not measure processing speed.

Try a local image

Use a Python 3.11-3.13 virtual environment and install the CPU backend:

pip install "rembg[cpu]==2.0.86"

Save an image you own as in.png, then run the code above. The first use downloads the selected model. Keep the original and review the transparent result before sharing it. The command-line interface requires the separate cli extra; the code here does not use it.

Limits and model choice

Only one drawing and one model were tested. We did not test real photos, people, hair, glass, overlapping objects, batches, GPU operation, web demos, server mode or cloud APIs. Do not infer quality on those from this drawing.

The project offers several models and optional cloud backends. Read each model's source and terms before choosing it. The library's MIT licence does not make all model choices equivalent. Our explicit u2net route is the one covered here.
