AI LANGUAGE TOOLS

fastText: identify text language locally, with limits

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

fastText offers a compact pretrained model for guessing the language of text on your computer. It can be useful for suggesting language labels before you review or sort documents. We tested six made-up strings. English, Malayalam-script and Hindi-script sentences returned the expected labels, but romanized Malayalam was labelled French. Very short text and digits also received language labels. This is a useful tool to inspect, not a reason to trust every prediction.

Quick facts

  • Model: the official page lists 176 supported languages and two original model files. We tested only lid.176.ftz, the compressed version listed as 917kB. We did not test all 176 languages.
  • Separate licences: the fastText code is MIT-licensed; the original language-ID models are listed under Creative Commons Attribution-Share-Alike 3.0. Check model terms separately; this is not a legal conclusion about your data or outputs.
  • Setup tested: fasttext 0.9.3, NumPy 1.26.4, Python 3.10/Linux. We pinned an isolated environment because a preliminary NumPy 2 setup hit an array-copy error.
  • Cost: no account, API key, payment or card was requested. The code and model are downloadable under their stated licences, with no paid service used in this test.
  • Privacy scope: the script returned identical results with networking disabled after package/model download. This is one observation, not a network audit.
  • India: the supported-language list includes hi and ml. India-specific availability was not established; this was a local installation, not an India-location test.

When it helps

A small local script can suggest a language label for a note before a separate review or processing step. It does not translate the text or establish the writer's identity, nationality or preferred language. Keep ambiguous text for manual review instead of silently routing it based on one label.

Our six-string test

On 28 October 2026 we loaded lid.176.ftz with official fasttext 0.9.3 on CPU. We supplied three short language samples, a romanized Malayalam sentence, the two-letter string "hi" and five digits. These are synthetic examples, not a representative accuracy benchmark.

Exact code

import fasttext
model = fasttext.load_model("lid.176.ftz")
samples = ["The library opens at nine.", "ലൈബ്രറി ഒൻപത് മണിക്ക് തുറക്കും.",
           "पुस्तकालय नौ बजे खुलता है।", "njan nale college-il varum", "hi", "12345"]
for text in samples:
    labels, scores = model.predict(text, k=1)
    print(repr(text), labels[0].removeprefix("__label__"), round(float(scores[0]), 3))

Copied output

'The library opens at nine.' en 0.875
'ലൈബ്രറി ഒൻപത് മണിക്ക് തുറക്കും.' ml 1.0
'पुस्तकालय नौ बजे खुलता है।' hi 0.989
'njan nale college-il varum' fr 0.216
'hi' en 0.125
'12345' en 0.125

The native-script samples returned en, ml and hi as intended. The romanized Malayalam sample returned fr, the French label, with score 0.216. The short string "hi" and digits returned en with score 0.125. The numbers are the model's returned scores, not independently measured correctness probabilities. The rounded 1.0 for one sample is not a guarantee of accuracy.

This configuration always asks for the top label. It has no rejection rule in our example, which is why a digit string still receives a language. We repeated the same code with networking disabled and obtained identical results.

Try the tested setup

Use an isolated Python 3.10 environment with a C++ build toolchain available. Our official package installation compiled native code:

pip install "fasttext==0.9.3" "numpy==1.26.4"

Download lid.176.ftz from the official model page, keep its terms and attribution information, and place it beside the script. The model expects UTF-8 text. The code above does not download it automatically.

Limits

  • Six chosen strings only. No accuracy score, speed benchmark, long documents, other models or all supported languages tested.
  • Romanized Malayalam failed in this example. We did not evaluate general romanized-language support, mixed-language documents or other transliteration styles.
  • Do not treat a top prediction or high score as certainty. We did not calibrate scores or design a production rejection threshold.
  • The current official docs also mention a separate newer NLLB model with different codes/licence. That is not the compact lid.176.ftz model tested here.
  • No screenshots or private documents were used. Code/output are selectable text, not a reconstructed terminal image.
