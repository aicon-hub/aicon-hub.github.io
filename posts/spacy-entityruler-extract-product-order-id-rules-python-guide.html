spaCy EntityRuler: extract fields with rules you can inspect

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

Not every text-processing step needs a language model to guess an answer. spaCy's EntityRuler lets you define the names and token patterns you want to extract, then returns matching text spans and labels. That can help a developer prepare a small, known vocabulary before later review or AI processing. We tested a fictional product name and an order-ID format. The rules found the expected forms, but also tagged an example ID and an ID in a sentence saying not to dispatch it.

Quick facts

  • Purpose: rule-based entity recognition using phrase or token patterns. The official API says it can run alone or alongside a statistical recognizer.
  • Tested setup: spaCy 3.8.18, Python 3.10.12/Linux, blank English pipeline. No pretrained model, API key or account used.
  • Licence and cost scope: the spaCy code repository lists MIT. No paid service or card was used. This article does not assess commercial support or other products.
  • Privacy scope: six made-up strings only. After installation, the script returned identical output with networking disabled. This is a bounded test, not a security audit.
  • India: no India-specific availability claim is established. We tested a local English rules workflow, not Malayalam, Hindi or an India-based network route.

Why use it beside a chatbot?

If your task is to find a known product name or a tightly specified ID form, editable rules let you inspect exactly what counts as a match. The result includes character offsets for locating the original span. A chatbot may help draft rules, but this script applies the same patterns without a generation prompt or an API call. This is useful for narrow extraction, not a general replacement for language understanding.

Our six-string test

On 28 October 2026, we used a blank English pipeline with two patterns: the phrase "Cedar Pro", matched case-insensitively, and one token matching ORD- followed by exactly four digits. All data is fictional. This is not a production order-processing system.

Exact code

import spacy
nlp = spacy.blank('en')
ruler = nlp.add_pipe('entity_ruler', config={'phrase_matcher_attr': 'LOWER'})
ruler.add_patterns([
    {'label': 'PRODUCT', 'pattern': 'Cedar Pro'},
    {'label': 'ORDER_ID', 'pattern': [
        {'TEXT': {'REGEX': r'^ORD-[0-9]{4}$'}}
    ]},
])
samples = [
    'Cedar Pro: dispatch ORD-1042.',
    'cedar pro: dispatch ORD-2048.',
    'CedarPro: dispatch ORD-1042.',
    'Cedar Pro: dispatch ORD-42.',
    'Do not dispatch ORD-1042 for Cedar Pro.',
    'ORD-9999 is only an example, not an order.',
]
print('spaCy', spacy.__version__, '| blank English | no trained model')
for text in samples:
    print(text)
    print([(e.text, e.label_, e.start_char, e.end_char) for e in nlp(text).ents])

Copied output

spaCy 3.8.18 | blank English | no trained model
Cedar Pro: dispatch ORD-1042.
[('Cedar Pro', 'PRODUCT', 0, 9), ('ORD-1042', 'ORDER_ID', 20, 28)]
cedar pro: dispatch ORD-2048.
[('cedar pro', 'PRODUCT', 0, 9), ('ORD-2048', 'ORDER_ID', 20, 28)]
CedarPro: dispatch ORD-1042.
[('ORD-1042', 'ORDER_ID', 19, 27)]
Cedar Pro: dispatch ORD-42.
[('Cedar Pro', 'PRODUCT', 0, 9)]
Do not dispatch ORD-1042 for Cedar Pro.
[('ORD-1042', 'ORDER_ID', 16, 24), ('Cedar Pro', 'PRODUCT', 29, 38)]
ORD-9999 is only an example, not an order.
[('ORD-9999', 'ORDER_ID', 0, 8)]

The lower-case product matched because we set phrase_matcher_attr to LOWER. "CedarPro" did not match the two-word phrase. ORD-42 did not match the four-digit rule. Both are useful boundaries to inspect rather than assume away.

The two last examples are the safety lesson: a syntactically matching ID still gets tagged in a negated instruction or a sentence saying it is only an example. A match is not proof that an order exists or that anyone approved dispatch. Never turn these labels directly into fulfilment actions.

We repeated the script in a process with networking disabled and compared the outputs byte-for-byte. They matched. Package installation still required a download first.

Try the tested route

Use a Python 3.10 environment and install the version we tested:

pip install "spacy==3.8.18"
python demo.py

Save the code above as demo.py. No spacy download model command is needed for this blank-pipeline example. The tested release's package metadata requires Python 3.10 or later, below 3.16.

Limits to keep visible

  • This is rule-based matching inside an NLP library, not generative AI or a trained entity recognizer.
  • Only six synthetic strings and two patterns were tested. No accuracy or speed benchmark, files or bulk pipeline was evaluated.
  • Case handling was configured explicitly. Spelling variations, missing spaces, multilingual text and context need their own rules and tests.
  • Token patterns depend on tokenization. A regular expression on one token is not the same as searching the whole raw string.
  • The official docs explain overlap priority and combining EntityRuler with a trained recognizer. Those combinations were not tested here.
