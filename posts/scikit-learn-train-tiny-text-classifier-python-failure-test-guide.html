scikit-learn: train a tiny text classifier and see its limits

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

scikit-learn is an open-source machine-learning library for Python. You can give it labelled examples and train a model to assign a category to new text. Our tiny experiment used twelve made-up college messages and three categories: hostel, library and transport. It classified three clear examples as intended, but also assigned unrelated text to hostel. That is a useful lesson: getting a label is not proof that the input belongs in any of the available categories.

Quick facts

  • What it is: the official site documents tools for classification, regression, clustering and other machine-learning tasks. This example is supervised text classification, not a chat model.
  • Licence: scikit-learn uses the BSD-3-Clause licence.
  • Tested version: scikit-learn 1.7.2 with Python 3.10. The 1.7.2 package metadata lists Python 3.10 or newer. We pinned that version for this example; it is not a claim that it is the newest release.
  • Cost: free open-source library. No API key, account, payment or card was requested.
  • Privacy scope: after installation, this script trained and predicted with networking disabled and produced identical output. No external model or dataset download was used. This is one test, not a network audit.
  • India: India-specific availability was not established. This was a local software test, not an India-location test.

Why try this?

It is a small, inspectable way to learn how training examples, labels and predictions fit together. You write the categories and examples yourself, then see what happens on new text. It can be the start of a classroom project about sorting messages, but this tiny dataset is not suitable for routing real student requests or making decisions about people.

Our local experiment

On 28 October 2026 we ran scikit-learn 1.7.2 on Linux/Python 3.10. A pipeline combined TF-IDF text features with a Multinomial Naive Bayes classifier, following the pattern described in the official text tutorial. All training and test strings below are made up. No inbox, personal notes or private messages were used.

Exact code

from sklearn.pipeline import make_pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.naive_bayes import MultinomialNB

train = [
    "Pay hostel rent and room fee", "Hostel room repair request",
    "Room allocation and hostel rules", "Mess food and hostel dining",
    "Library book loan and return", "Renew borrowed library books",
    "Library opening hours and reading room", "Book reservation at the library",
    "Bus route and college transport", "Bus timetable morning departure",
    "Transport pass renewal for bus", "College bus stop and ticket",
]
labels = ["hostel"] * 4 + ["library"] * 4 + ["transport"] * 4
model = make_pipeline(TfidfVectorizer(), MultinomialNB())
model.fit(train, labels)
tests = ["hostel room fee", "renew library books", "morning bus timetable",
         "rent and library book", "quantum banana telescope"]
for text, label in zip(tests, model.predict(tests)):
    print(repr(text), "->", label)

Copied output

'hostel room fee' -> hostel
'renew library books' -> library
'morning bus timetable' -> transport
'rent and library book' -> library
'quantum banana telescope' -> hostel

The failure matters

The clear hostel, library and bus examples returned their intended categories. The mixed message "rent and library book" was assigned library, even though it contains two topics. The unrelated "quantum banana telescope" was assigned hostel. With this setup, predict chooses one of the trained labels; there is no "unknown" label or rejection rule.

For this exact training vocabulary, none of the unrelated sentence's words appears in training. The vectorizer therefore gives that input no matching word features. Do not interpret its label as evidence that the sentence concerns hostel life. We did not measure accuracy, and five hand-chosen test strings are not a validation benchmark.

Try it

pip install "scikit-learn==1.7.2"

Use Python 3.10 or newer in a virtual environment, then run the code above. Change one training example at a time and inspect the effect. Keep the test examples separate from training. For a real project you would need representative labelled data, independent evaluation and a design for ambiguous or out-of-scope inputs, rather than treating every prediction as reliable.

Limits

  • Twelve short English training strings and five hand-picked test strings. No large dataset, Hindi, Malayalam, spelling mistakes, long text or real message routing tested.
  • This is a statistical text classifier, not semantic search, keyword extraction or a generative assistant. It does not explain whether the category is appropriate.
  • No production deployment, confidence calibration, fairness study or model-quality benchmark. A label is not an assurance of relevance.
  • Code and output are selectable text, not a reconstructed terminal screenshot. No pretrained model or sample files need downloading beyond package installation.
