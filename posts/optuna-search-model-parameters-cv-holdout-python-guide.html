Optuna: search model settings without reusing the test set

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

Optuna runs a search over model settings and records the score returned by each trial. That can replace a hand-written loop when you want to try several settings. We tested a small local search over decision-tree depth and minimum leaf size, using cross-validation inside the training data. We kept a separate holdout out of the search. This is a lesson in setting up a search, not evidence that tuning always improves a model.

Quick facts

  • Purpose: a Python hyperparameter-optimization framework. You define an objective, suggest parameter ranges and set a trial budget.
  • Tested: Optuna 5.0.0, scikit-learn 1.7.2, Python 3.10.12/Linux. Twelve sequential trials, two integer parameters, seeded TPE sampler.
  • Cost and licence: the official repository lists MIT. No account, API key, payment, card or paid compute was used. Real searches still consume your own compute or a provider's paid resources.
  • Privacy scope: bundled Wine data only. After installation, the full script returned identical output with networking disabled. Not a security audit.
  • India: no India-specific access claim established. This was a local package test, not an India-network availability check.

Why use it beside a chatbot?

A chatbot can suggest parameter ranges, but Optuna actually calls your objective repeatedly and tracks trial results. Unlike a tracking-only tool, it also selects candidate settings through a sampler. It cannot fix a misleading objective, data leakage or a poor validation design. Those decisions still need review.

Our bounded test

On 28 October 2026, we split the bundled Wine dataset into 133 training rows and 45 held-out rows using a fixed seed and stratification. Each trial evaluated a decision tree with three-fold cross-validation on the training rows only. The search maximized mean CV accuracy over 12 trials. Only afterward did we fit the selected settings on all training rows and score the held-out set once.

Exact tested code

import optuna
import sklearn
from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.tree import DecisionTreeClassifier
optuna.logging.set_verbosity(optuna.logging.WARNING)
X, y = load_wine(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y)
def objective(trial):
    depth = trial.suggest_int('max_depth', 1, 8)
    leaf = trial.suggest_int('min_samples_leaf', 1, 6)
    model = DecisionTreeClassifier(max_depth=depth,
                                   min_samples_leaf=leaf, random_state=42)
    return cross_val_score(model, X_train, y_train, cv=3,
                           scoring='accuracy').mean()
study = optuna.create_study(direction='maximize',
    sampler=optuna.samplers.TPESampler(seed=42))
study.optimize(objective, n_trials=12)
best = DecisionTreeClassifier(**study.best_params, random_state=42)
best.fit(X_train, y_train)
print('Optuna', optuna.__version__, '| scikit-learn', sklearn.__version__)
print('trials:', len(study.trials), '| training rows:', len(y_train),
      '| untouched holdout rows:', len(y_test))
print('best parameters:', study.best_params)
print('best 3-fold CV accuracy:', round(study.best_value, 6))
print('final holdout accuracy:', round(best.score(X_test, y_test), 6))
print('first 3 trial scores:', [round(t.value, 6) for t in study.trials[:3]])

The selected settings were max_depth=8 and min_samples_leaf=1. The mean CV score was 0.849495 and the final holdout score was 0.955556. These evaluate different row sets; a higher holdout score is not proof of improvement over the CV score. We did not compare a baseline, other samplers or a larger trial budget.

The script was repeated with networking disabled after package installation; output matched byte-for-byte. No model download was needed for the bundled dataset and decision tree.

Run this exact route

Use an isolated Python 3.10 environment, install the tested versions, save the code as demo.py and run it:

pip install "optuna==5.0.0" "scikit-learn==1.7.2"
python demo.py

The tested release metadata lists Python 3.9 or later; the current project homepage recommends Python 3.10 or newer. We tested Python 3.10.12, not Python 3.9. This study lives in memory; its trial history is not saved to disk by this code. A fixed seed helps reproduce this sequential example in the same environment, not every parallel run or future dependency version.

Before adapting it

  • Set a trial or time budget. Every trial can retrain a model and cost time or money.
  • Keep test data out of the objective. Repeatedly choosing settings based on the holdout makes that holdout less useful as a final check.
  • This small dataset is not a production benchmark. No generalization guarantee, statistical significance, fair comparison or universal best setting is claimed.
  • No pruning, parallel search, dashboard, persistent storage, LLM tuning or remote compute was tested.
  • The objective determines what is optimized. A good trial score does not establish safety, fairness or usefulness.
