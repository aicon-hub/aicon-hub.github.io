SHAP: inspect contributions to a tree prediction

By AiCoN | Published 28 October 2026 | Sources checked 28 October 2026

A model can return a number without showing which inputs contributed to that output. SHAP's TreeExplainer calculates feature contributions for supported tree models. We tested one synthetic regression-tree prediction: the output 22 equalled baseline 16 plus contributions 5 and 1. That verifies the arithmetic for this configuration. It does not prove the model is accurate or that changing an input causes a real-world outcome.

Quick facts

  • Purpose: inspect a model output through feature contributions relative to a baseline. The TreeExplainer reference describes supported tree models, output types and feature-dependence assumptions.
  • Tested: SHAP 0.49.1, scikit-learn 1.7.2, Python 3.10.12/Linux. One fitted decision-tree regressor, eight artificial rows and two features.
  • Version scope: 0.49.1 was the version installed for Python 3.10. The current 0.54.1 package requires Python 3.12 or later; we did not test it.
  • Cost and licence: the code repository lists MIT. No account, API key, card, payment or cloud service used.
  • Privacy scope: fictional data only. After installation, the full script returned identical output with networking disabled. Not a security audit.
  • India: no India-specific availability established. This is a local code workflow, not a regulated decision or causal assessment.

Why use it beside a chatbot?

A chatbot can describe feature importance in general. TreeExplainer computes contributions from your actual fitted model and selected row under an explicit explanation setup. You can then check whether the baseline plus contributions reconstructs the output. It explains model behaviour under assumptions, not the true reason something happened in the world.

Our small test

On 28 October 2026 we created eight fictional rows and targets from 10 times feature 0 plus 2 times feature 1. We fitted a decision-tree regressor to those rows. This is a controlled explanation exercise, with no holdout or claim of predictive performance.

Exact tested code

import numpy as np
import shap
import sklearn
from sklearn.tree import DecisionTreeRegressor
# Fictional data; units have no real-world interpretation.
X = np.array([[0,0], [0,1], [1,0], [1,1],
              [2,0], [2,1], [3,0], [3,1]])
y = 10 * X[:, 0] + 2 * X[:, 1]
model = DecisionTreeRegressor(random_state=42).fit(X, y)
row = np.array([[2, 1]])
explainer = shap.TreeExplainer(model,
    feature_perturbation='tree_path_dependent', model_output='raw')
explanation = explainer(row)
base = float(explanation.base_values[0])
values = explanation.values[0]
prediction = float(model.predict(row)[0])
print('SHAP', shap.__version__, '| scikit-learn', sklearn.__version__)
print('row:', row[0].tolist())
print('prediction:', prediction)
print('base:', base)
print('contributions:', values.tolist())
print('base + contributions:', base + values.sum())
print('sum matches prediction:', np.isclose(base + values.sum(), prediction))

Copied output

SHAP 0.49.1 | scikit-learn 1.7.2
row: [2, 1]
prediction: 22.0
base: 16.0
contributions: [5.0, 1.0]
base + contributions: 22.0
sum matches prediction: True

For row [2, 1], the model predicted 22.0. The explanation returned baseline 16.0 and contributions [5.0, 1.0]; the sum matched 22.0. Contributions are relative to the explanation's baseline, not the same as the coefficients 10 and 2 used to construct the targets.

We explicitly chose tree_path_dependent and raw output. Other background data or feature-dependence assumptions can produce different explanations. The baseline is not a universal average for every model or explainer configuration.

The same script returned identical output with networking disabled after installation. No external dataset or pretrained model was downloaded for this test.

Run the pinned route

Use an isolated Python 3.10 environment. Install the tested versions, save the code as demo.py and run:

pip install "shap==0.49.1" "scikit-learn==1.7.2"
python demo.py

This example explains the raw numeric output of a regressor. Do not relabel contributions from a classifier as probabilities without checking its model_output setting and supported explanation mode.

Limits to keep visible

  • One row, two features, one tiny fitted tree. No benchmark, global explanation, image/text model or production system was evaluated.
  • Additivity checks the reconstruction, not truth, model quality, fairness or causal validity.
  • Feature dependence and background choices affect interpretation. Correlated inputs need care.
  • The official causal-interpretation warning explains why exposing correlations in a predictive model does not make them causal. Do not use this example as advice about what intervention to make.
  • No plot or dashboard tested. Code and copied output are selectable text, not a reconstructed terminal screenshot.
