WisdomAI Live Apps: build analytics apps, check data and control access

By AiCoN | Published 7 October 2026 | Sources checked 7 October 2026

WisdomAI Live Apps turn a plain-language request into an interactive app on governed company data. They are not a free public website builder, and 'live' means the latest refreshed results, not a real-time stream.

What is a Live App?

A Live App is a generated interface for a job such as a sales pipeline review or an executive KPI overview. KPI means a key performance indicator: a number your team uses to track progress. The app combines charts, tables, filters and questions using data already set up in WisdomAI domains.

A domain carries the relevant data, definitions and context for analysis. Clear metric names, synonyms and business rules improve the result. A prompt cannot repair a poorly defined revenue metric or missing data permissions by itself.

What makes it governed?

The documentation says row-level and column-level security, domain permissions and metric definitions carry over from dashboards. Queries run as the person viewing the app. Two people can open the same app and see different data because they have different access.

Row-level rules limit which records a person can see. Column-level rules limit fields such as a salary or contact detail. The generated app runs in a sandbox and shows data served through WisdomAI. This is a controlled analytics interface, not permission for the app to access any company database.

Who can create an app?

The official documentation says Live Apps is generally available to all users within the product. Explorer roles and above can create apps. View-only users can open apps shared with them but cannot build or edit them. General availability does not mean that anyone on the internet has a free account.

Existing dashboards keep working. Apps and dashboards sit together under Apps, and new builds default to apps. A dashboard is a hand-arranged grid of tiles; a Live App is organized around the task described in your prompt.

Is it free, and can Indian teams use it?

The pages reviewed provide an enterprise demo route but no public fixed subscription price or permanent free personal tier. Treat it as an enterprise purchase that needs a quote. Ask about user roles, query usage, data connections, support, trial length and costs for the warehouse that serves the data.

No India-specific availability or hosting commitment was established by these pages. An Indian team should confirm contract eligibility, data location, required connectors and security terms with WisdomAI. A public demo or an accessible homepage does not prove that your organization can deploy it in its required region.

How to build a useful first app

  1. Check that your role can create apps and that the data domain has approved metrics.
  2. Open Apps in the sidebar and select New App.
  3. Describe the audience, job, metrics, breakdowns and views. For example: a weekly sales review using the team's defined revenue and pipeline metrics.
  4. Let WisdomAI answer the data questions, generate the app and validate it. The build continues on the server if you leave the page.
  5. Return to check the result. The guide says there is no notification when generation finishes.
  6. Check the figures against a trusted report before treating them as correct.
  7. Refine through chat, annotations or direct text edits.
  8. Review access before sharing the app with the intended team.

Check the numbers underneath

The Sources view shows the widgets behind the interface. A widget is the query-backed object supplying a chart, table or number. The documentation says you can inspect how it was calculated, the SQL query and a preview of the data. SQL is the language used to ask a database for records.

Check time periods, currencies, excluded records and metric definitions. A neat chart can still answer the wrong question. Inspect results using different authorized roles so restricted data stays restricted.

Refresh is not real-time streaming

Apps show the latest refreshed widget results. They refresh automatically on a schedule and can be updated on demand with Refresh data. The documentation explicitly says they do not stream updates in real time. Instant filtering narrows loaded data; filters that re-run the warehouse query are listed as coming soon.

For a time-sensitive decision, check the refresh time and the source system's own delay. Do not assume a newly opened app includes a transaction that arrived seconds ago.

Sharing and editing need care

Viewers can filter, annotate and ask follow-up questions within their own view. Changing the shared app requires editor access. The creation guide warns that Live Apps have no separate draft version: changes affect the app everyone sees. Duplicate an app for experiments or refine it before broad sharing. Version history can restore an earlier state.

Download HTML packages the app and its current data into an interactive file. CSV exports contain widget data. Treat downloaded files as separate data disclosures; do not assume the live app's access controls protect a file after someone forwards it. PowerPoint download is marked coming soon.

What changed since the original post?

The original post emphasized hosted apps, governed data and follow-up analysis. Current documentation adds exact creation roles, source inspection, scheduled refresh, export options and the lack of a separate draft. The product page mentions MCP and Python tools, but those marketing claims do not show that every app supports every forecast. We did not connect a company dataset or test a workspace.

FAQ

Do I need to move every dashboard now?

No. Existing dashboards continue working; migration is optional.

Can a viewer edit the shared app?

No. Viewer interactions affect their own view. App changes need editor access.

Are the data always current to the second?

No. Live Apps serve the latest refreshed results, not a real-time stream.
